1. The Problem Statement & Architecture

Large Language Models (LLMs) are inherently stateless. Out of the box, they suffer from three critical limitations:

  • Amnesia: Every API call is a blank slate. The LLM has no memory of previous conversational turns.
  • Paralysis: LLMs can only generate text. They cannot interact with the real world (e.g., read files, do exact math).
  • Lack of Autonomy: They answer one question at a time. They cannot independently break down a multi-step problem.
The Khwarizm Solution: We solve this by wrapping the stateless LLM inside an intelligent, autonomous Agent Object that manages persistent memory, a registry of executable tools, and an autonomous reasoning loop.

↓
⚙️ BaseAgent
AgentConfig Identity, Rules, Max Iters
BaseLLM (The Brain) GroqClient / GeminiClient
ToolRegistry (The Hands) Calculator, File I/O
Memory (The Context) ShortTerm (RAM) + LongTerm (JSON)
↓
FINAL ANSWER / ACTION

3. Object-Oriented Programming (OOP) Audit

Khwarizm is built strictly on the pillars of Object-Oriented Design. Every decision prioritizes loose coupling and high cohesion.

Abstraction

We use Python's abc module to enforce contracts. BaseLLM, BaseTool, and BaseMemory guarantee that any concrete implementation will have the necessary methods (generate, run, add_entry).

from abc import ABC, abstractmethod

class BaseLLM(ABC):
    @abstractmethod
    def generate(self, sys, user) -> str:
        pass
Composition (vs Inheritance)

The agent HAS A memory and HAS A LLM. It is not a type of memory or LLM. Composition models reality better here and allows us to hot-swap components.

class BaseAgent:
    def __init__(self, llm: BaseLLM, ...):
        self.llm = llm
        self.registry = ToolRegistry()
        self.__short_term = ShortTermMemory()
Polymorphism

The BaseAgent works identically with different LLM providers. It relies on the shared interface, not the concrete class.

# Identical agent code, different brains
groq_agent = BaseAgent(llm=GroqClient())
gemini_agent = BaseAgent(llm=GeminiClient())
Encapsulation & Properties

Double underscores hide internal data. @property decorators provide safe, read-only public access.

@property
def name(self) -> str:
    # User types agent.name safely
    return self.config.name
Exception Handling

All critical operations wrapped in try/except blocks. Network failures and file corruption return clean error messages instead of crashes.

try:
    response = self.client\
        .chat.completions.create(...)
    return response.choices[0]\
        .message.content
except Exception as e:
    return f"Error: {str(e)}"
Inheritance

TaskAgent and ConversationalAgent inherit from BaseAgent, overriding the default initialization to provide specific, role-based system prompts using super().__init__().

4. Deep Dive: AgentConfig & Dataclasses

In standard Python, data-container classes require massive amounts of repetitive boilerplate. We utilize the @dataclass decorator to automatically generate __init__ and __repr__ methods.

Data Validation via __post_init__

Dataclasses provide a __post_init__ hook that executes immediately after instantiation. We use this as our "HR Officer" to ensure the user didn't provide invalid parameters.

@dataclass
class AgentConfig:
    name: str
    description: str
    system_prompt: str = "You are a helpful AI assistant"
    max_iterations: int = 10

    def __post_init__(self):
        if self.max_iterations <= 0:
            raise ValueError("max_iterations must be > 0")

The Default Argument Rule: Python strictly enforces that fields with default values (like max_iterations) must come after mandatory fields (like name).

5. Deep Dive: The BaseAgent Class

The BaseAgent is the central orchestrator. Let's break down its specific methods.

__init__(self, name, llm, system_prompt, tools)

The constructor handles complex wiring automatically so the user doesn't have to:

  1. Auto-Registration: It takes the tools list and loops through it, passing each object to the ToolRegistry.
  2. Prompt Injection: It fetches the tool descriptions from the registry and injects them directly into the system prompt, alongside the strict formatting rules for tool execution.
  3. Memory Initialization: It spins up both ShortTermMemory and LongTermMemory seamlessly.

__handle_tool_call(self, response)

This is the string-parsing engine. When the LLM outputs a tool request, this method:

  1. Splits the text line by line.
  2. Searches for TOOL: and INPUT: tags.
  3. Uses a break statement the moment it finds a complete pair. (Why? Smart LLMs sometimes try to output 5 tool calls at once. We force execution one-at-a-time to ensure the memory state is accurately updated before the next decision).
  4. Fetches the physical Python object from the Registry, calls .run(), and returns the result.

6. Deep Dive: The Agentic Loop (ReAct)

The run() method contains a while loop. This is the implementation of the industry-standard Reason + Act (ReAct) architecture.

Analogy: The Amnesiac Surgeon. An LLM forgets everything between API calls. Imagine a surgeon doing a complex operation, but getting amnesia every 5 seconds. To solve this, a nurse reads the entire "Surgery Log" (Memory) out loud before every step. The loop constantly feeds the LLM its own growing history so it knows exactly what to do next.

Algorithm Flow:

  1. Save the User's input to Memory.
  2. Loop Starts: Counter increments. If counter > max_iterations, return an error (prevents infinite token burning).
  3. Combine Short Term and Long Term memory into full_context.
  4. Send to LLM.
  5. Strip <think> tags if a reasoning model is used (keeps the prompt size small and fast).
  6. Check for the word TOOL:.
    • If YES: Call __handle_tool_call(). Save the action and the tool result to Short Term Memory. continue the loop.
    • If NO: The LLM has found the final answer. Save to memory, break the loop, and return the answer.

7. Deep Dive: The Dual-Memory System

Khwarizm implements two distinct memory layers that are combined at runtime.

ShortTermMemory (STM)

Implemented as a Python list. It acts as the agent's RAM. It tracks the back-and-forth tool outputs and thoughts during a single run() loop. When the script exits, it is destroyed.

LongTermMemory (LTM)

Implemented via Python's json and os modules. It saves the final answers and user inputs to a persistent JSON file. If you restart the computer, the agent still remembers the conversation.

Memory Roles

Messages are saved with specific roles to maintain semantic clarity for the LLM:

  • user: Human input.
  • assistant: The LLM's response or tool-call request.
  • tool: (Formerly system). Represents the physical observation returned by Python executing a tool. Separating this from "system" prevents the LLM from confusing a tool output with developer instructions.

8. Deep Dive: The Tool Registry System

Class Variables vs Instance Variables

In BaseTool, name and description are defined as Class Variables. Why? Because every instance of CalculatorTool will always have the exact same name and description. Storing them at the class level saves memory and enforces consistency.

The Registry: Dictionary vs List

The ToolRegistry stores tools in a private dictionary (self.__tools = {}), rather than a list. This is a deliberate performance decision.

Big-O Notation: Searching a list is O(n) time. If you have 1,000 tools, the program might check 1,000 items to find the right one. A dictionary lookup is O(1) time. Python hashes the string key and jumps instantly to the tool in memory. 1 tool or 1,000,000 tools, it always takes 1 step.

Auto Registration Flow

# User just passes a list. Framework handles everything.
agent = BaseAgent(
    name="SmartBot",
    llm=my_llm,
    tools=[CalculatorTool(), FileWriterTool(), FileReaderTool()]
)
# Internally: loops through list, registers each tool,
# builds descriptions, injects into system prompt automatically.

9. Advanced Multi-Agent Workflows

Khwarizm does not require complex routing classes to build multi-agent systems. Because the architecture dictates that agents receive a string and return a string, they can be chained together using native Python constructs.

The Actor-Critic Pattern

Two separate instances of TaskAgent, with separate memory banks, interacting via a native Python loop.

# 1. Initialization
writer = TaskAgent(name="Writer", llm=llm, tools=[FileWriterTool()])
critic = TaskAgent(name="Critic", llm=llm, tools=[FileReaderTool()])

# 2. Native Python Orchestration Loop
for attempt in range(3):
    writer.run("Write a python script in app.py")

    feedback = critic.run("Read app.py. Output PASS if perfect, otherwise output errors.")

    if "PASS" in feedback:
        print("Code verified!")
        break
    else:
        # Feed critic's output directly back into the writer
        writer.run(f"Fix the code based on this feedback: {feedback}")

agents/baseagent.py

from config import AgentConfig
from clients.basellm import BaseLLM
from tools.registry import ToolsRegistry
from memory.stm import ShortTermMemory
from memory.ltm import LongTermMemory

class BaseAgent:
    def __init__(self, name, llm: BaseLLM, system_prompt: str = "You are a helpful AI assistant", tools: list = None):
        self.llm = llm
        self.registry = ToolsRegistry()
        tools = tools or []
        for tool in tools:
            self.registry.register(tool)

        if tools:
            tool_info = self.registry.get_descriptions()
            system_prompt = (
                f"{system_prompt}\n\n"
                f"You have access to these tools:\n"
                f"{tool_info}\n\n"
                f"To use a tool, respond EXACTLY in this format:\n"
                f"TOOL: tool_name\n"
                f"INPUT: your input here"
            )

        self.config = AgentConfig(
            name=name,
            description="A basic agent",
            system_prompt=system_prompt
        )
        self.__short_term = ShortTermMemory()
        self.__long_term = LongTermMemory(agent_name=name)

    def run(self, user_input: str) -> str:
        self.__short_term.add_entry(role="user", content=user_input)
        self.__long_term.add_entry(role="user", content=user_input)

        iterations = 0
        max_iters = self.config.max_iterations

        while iterations < max_iters:
            iterations += 1

            long_term_context = self.__long_term.get_context()
            short_term_context = self.__short_term.get_context()

            full_context = (
                f"Past Conversations:\n{long_term_context}\n\n"
                f"Current Session:\n{short_term_context}"
            )

            response = self.llm.generate(
                system_prompt=self.config.system_prompt,
                user_prompt=full_context
            )

            if "TOOL:" in response:
                tool_note = self.__handle_tool_call(response)

                self.__short_term.add_entry(
                    role="assistant",
                    content=response
                )
                self.__short_term.add_entry(
                    role="tool",
                    content=tool_note
                )
                continue

            self.__short_term.add_entry(role="assistant", content=response)
            self.__long_term.add_entry(role="assistant", content=response)

            return response

        return "Error: Agent reached maximum iterations."

    def __handle_tool_call(self, response: str) -> str:
        lines = response.strip().split("\n")
        tool_name, tool_input = None, None

        for line in lines:
            if line.startswith("TOOL:"):
                tool_name = line.replace("TOOL:", "").strip()
            elif line.startswith("INPUT:"):
                tool_input = line.replace("INPUT:", "").strip()

            if tool_name and tool_input:
                break

        tool = self.registry.get_tool(tool_name)

        if not tool:
            return f"Error: Unknown tool '{tool_name}'"

        return f"Tool '{tool_name}' returned: {tool.run(tool_input)}"

clients/groqclient.py

from groq import Groq
from clients.basellm import BaseLLM

class GroqClient(BaseLLM):
    def __init__(self, model: str = "llama3-8b-8192"):
        self.client = Groq()
        self.model = model

    def generate(self, system_prompt: str, user_prompt: str) -> str:
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_prompt}
            ]
        )
        return response.choices[0].message.content

tools/registry.py

from tools.basetool import BaseTool

class ToolsRegistry:
    def __init__(self):
        self.__tools = {}

    def register(self, tool: BaseTool):
        self.__tools[tool.name] = tool

    def get_tool(self, name: str) -> BaseTool:
        return self.__tools.get(name)

    def get_descriptions(self) -> str:
        descriptions = []
        for name, tool in self.__tools.items():
            descriptions.append(f"- {name}: {tool.description}")
        return "\n".join(descriptions)

    def list_tools(self) -> list:
        return list(self.__tools.keys())

memory/stm.py

from memory.basememory import BaseMemory

class ShortTermMemory(BaseMemory):
    def __init__(self):
        self.__history = []

    def add_entry(self, role: str, content: str):
        self.__history.append({
            "role": role,
            "content": content
        })

    def get_context(self) -> str:
        if not self.__history:
            return ""

        context = ""
        for entry in self.__history:
            context += f"{entry['role']}: {entry['content']}\n"
        return context

    def clear(self):
        self.__history = []

utils/chat_ui.py

def start_terminal_chat(agent):
    """A reusable terminal chat interface for any agent."""
    print("=" * 50)
    print(f"Starting chat with: {agent.name}")
    print("Type 'exit' to quit, or 'clear' to wipe memory.")
    print("=" * 50)

    while True:
        user_input = input("\nYou: ")

        if user_input.lower() in ["exit", "quit"]:
            print(f"{agent.name}: Goodbye!")
            break

        if user_input.lower() == "clear":
            agent.clear_memory()
            continue

        response = agent.run(user_input)
        print(f"\n{agent.name}: {response}")

Frequently Asked Questions

Q: Why use Composition over Inheritance for the Agent?
A: Because the Agent HAS a brain (LLM) and HAS hands (Tools). It is not A TYPE of brain or A TYPE of tool. Composition models reality better and enables hot-swapping components.
Q: Why do we have both ShortTerm and LongTerm Memory?
A: ShortTerm acts as RAM for the current session. LongTerm persists across restarts via JSON files. Together they give the agent both immediate context and historical knowledge.
Q: What is the Agentic Loop?
A: A while loop that keeps asking the LLM what to do next. If the LLM wants to use a tool, we run the tool, save the result to memory, and loop again. If the LLM gives a final answer with no tool call, we break the loop and return the answer.
Q: Why a dictionary in the ToolRegistry?
A: Dictionaries provide O(1) lookup time. With 1,000 tools, a list would require checking up to 1,000 items. A dictionary jumps directly to the tool in 1 step.
Q: What would you improve next?
A: A SupervisorAgent for multi-agent orchestration, a Streamlit web frontend, and proper logging instead of print statements.
